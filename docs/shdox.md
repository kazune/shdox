# shdox 仕様

shdox は Bash 関数のドキュメントコメントを検証・整形し、ドキュメントを生成する CLI です。

## ドキュメントコメント

Bash の構文上コメントに当たり、行頭またはスペース・タブによるインデントの直後から `##` で始まる独立した行は、すべてドキュメントコメントの候補です。
コマンド末尾のコメントや、ヒアドキュメント・引用文字列内のコメント風文字列は対象外です。
連続する候補行を1つのブロックとし、各ブロックは関数宣言の直前に置きます。
ブロックと関数宣言の間に空行や通常のコメントを挟んだ場合、および対応する関数宣言がない場合は配置エラーです。
`### 見出し` のように本文の区切りを欠く候補行は構文エラーです。
条件分岐内や別の関数内にある宣言にも同じ規則を適用します。
ドキュメントのない関数も許容します。
概要は必須の1行で、詳細説明とタグはそれぞれ省略できます。
セクション間と詳細説明の段落間には、コメント空行を厳密に1行置きます。
タグ間とブロック末尾にコメント空行は置けません。

```sh
## ファイルを検証する。
##
## ファイルの存在を確認する。
## 存在しない場合はシェルを終了する。
##
## 空ファイルは検証失敗として扱う。
##
## @param $1 ファイルパス
## @return 0 検証成功
## @return 1 空ファイル
## @exit 2 ファイルが存在しない
validate_file() {
    [[ -f "$1" ]] || exit 2
    [[ -s "$1" ]] || return 1
    return 0
}
```

### 行の解析

1. 行末の水平空白を解析時に除去します。
2. `##` だけの行をコメント空行として扱います。
3. 本文のある行では、`##` の直後に水平空白が1文字以上必要です。
4. `##` 直後の水平空白をすべて読み飛ばし、最初の文字が `@` ならタグ行、それ以外なら本文行として扱います。
5. タグ行では、タグ名と後続フィールドの間、および引数と説明文の間にある連続した水平空白を区切りとして読み取ります。

水平空白は ASCII スペースと水平タブで、同じ区切り内に混在できます。
本文とタグの説明文は必須の非空文字列で、改行を含めることはできません。
本文と説明文の内部の空白は自由に記述できます。
未定義のタグ名は検証エラーです。

### EBNF

この文法は行末の水平空白を除去した後の行に適用します。

```ebnf
document    = summary, [ blank, details ], [ blank, tags ];
summary     = text-line;
details     = paragraph, { blank, paragraph };
paragraph   = text-line, { text-line };
tags        = tag-line, { tag-line };

blank       = "##", newline;
text-line   = "##", separator, text, newline;
tag-line    = "##", separator, tag, newline;

tag         = "@param", separator, position, separator, description
            | "@return", separator, status, separator, description
            | "@exit", separator, status, separator, description
            | ( "@stdin" | "@stdout" | "@stderr" | "@sideeffect" ),
              separator, description;

position    = "$", nonzero, { digit };
status      = "0" | nonzero, { digit };
separator   = hspace, { hspace };
hspace      = ? ASCII スペースまたは水平タブ ?;
nonzero     = "1" | "2" | "3" | "4" | "5" | "6" | "7" | "8" | "9";
digit       = "0" | nonzero;
text        = ? 水平空白と @ 以外の文字で始まる非空の行内文字列 ?;
description = ? 水平空白以外の文字で始まる非空の行内文字列 ?;
newline     = ? 行の終端 ?;
```

### タグの意味と検証規則

| タグ | 意味 | 出現回数 |
| --- | --- | --- |
| `@param <position> <description>` | 位置引数の説明 | 0回以上 |
| `@return <status> <description>` | 関数から戻る際の終了ステータスの説明 | 0回以上 |
| `@exit <status> <description>` | シェルを終了する際の終了ステータスの説明 | 0回以上 |
| `@stdin <description>` | 標準入力の説明 | 0～1回 |
| `@stdout <description>` | 標準出力の説明 | 0～1回 |
| `@stderr <description>` | 標準エラー出力の説明 | 0～1回 |
| `@sideeffect <description>` | 副作用の説明 | 0回以上 |

位置引数は `$1` 以上の正整数で、先頭にゼロを付けることはできません。
終了ステータスは0～255の整数で、`0` 以外の表記では先頭にゼロを付けることはできません。
同一ブロック内では、同じ位置引数の `@param`、同じステータスの `@return`、同じステータスの `@exit` をそれぞれ重複して記述できません。
`@return 1` と `@exit 1` のように、種類の異なるタグで同じステータスを使うことはできます。
タグの並び順は任意です。

## CLI

### 共通の入力

各コマンドは1つ以上のファイル引数を受け取り、指定順に処理します。
`-` は標準入力を表し、ファイル引数と併用できますが、指定できるのは1回だけです。
入力引数の省略はコマンドラインの構文エラーで、ディレクトリの指定は入力エラーです。
入力は BOM なしの UTF-8 とし、BOM 付きの入力や不正な UTF-8 は入力エラーです。
LF と CRLF を行の区切りとして扱い、同一ファイル内での混在と最終改行の省略を許容します。

| コマンド | 動作 |
| --- | --- |
| `shdox check FILE...` | コメントの字句、構造、配置、値域を検証する。 |
| `shdox fmt [-d \| -w] FILE...` | コメントの構文上の区切りを ASCII スペース1文字に統一する。 |
| `shdox generate FILE...` | コメントからドキュメントを生成する。 |

`check` と `generate` の入力では、構文上の区切りに ASCII スペースと水平タブを混在させることができます。
検証範囲は字句と構造までとし、関数本体の制御フローとタグ記述の整合性は検証対象外です。

### 整形の出力

| オプション | 動作 |
| --- | --- |
| なし | 整形済みのソースを入力順に標準出力へ書き、入力間に区切り文字を追加しない。 |
| `-d` | 整形前後に差分がある入力について、ファイル名付きの unified diff を入力順に標準出力へ書く。 |
| `-w` | 入力ファイルを整形結果で上書きする。 |

各行の改行形式と、ファイル末尾の改行の有無を保持します。
`-d` と `-w` の併用、および `-w` での `-` の指定はコマンドラインの構文エラーです。
すべての入力の読み取りと検証が成功してから、出力または上書きを始めます。
上書き開始後に I/O エラーが発生した場合は、その時点で停止します。

### 終了コード

| 終了コード | 条件 |
| --- | --- |
| `0` | 処理に成功し、`fmt -d` の場合は差分がない。 |
| `1` | `fmt -d` の処理に成功し、差分がある。 |
| `2` | コマンドラインの構文エラー、Bash の構文エラー、ドキュメント違反、入力エラー、I/O エラーなどが発生した。 |

## 実装要件

Go で実装し、Bash の構文解析には `mvdan.cc/sh/v3/syntax` を使用します。
`LangBash` と `KeepComments(true)` を指定して解析し、`*syntax.FuncDecl` を関数宣言として扱います。
コメントと関数のソース位置を照合して、独立したコメント行、ブロックの連続性、関数宣言との隣接を判定します。

## 要確認事項

| 項目 | 確認する内容 |
| --- | --- |
| 対象と互換性 | Go とパーサーの採用バージョン。 |
| 診断 | 診断の出力先と形式、ファイル名・行番号・列番号の表記、複数エラーの報告順と処理の継続条件。 |
| 整形の詳細 | 行末空白の出力規則、diff のヘッダー表記、書き込み失敗時の部分更新の扱い。 |
| 生成の出力 | Markdown の採否と構成、出力先、複数関数・複数ファイルの順序、説明文のエスケープ、不正入力時の部分出力の扱い。 |

## 受け入れテスト項目

| 区分 | 確認する動作 |
| --- | --- |
| 正常系 | 概要のみ、概要と詳細、概要とタグ、全セクションを含む複数段落のブロックを受理する。 |
| 境界値 | `$1` と `$10`、ステータス `0` と `255`、単一出現タグの0回と1回を受理する。 |
| 不正入力 | `$0` と `$01`、ステータス `-1`・`00`・`256`、説明文の欠落、未知タグ、重複する引数・ステータス・単一出現タグを検出する。 |
| 配置違反 | セクション区切りの欠落、連続するコメント空行、タグ間・ブロック末尾のコメント空行、タグの後の本文、関数との間にある空行を検出する。 |
| 空白 | スペースとタブの混在、行末の水平空白、水平空白だけが続く `##` を受理し、`fmt` は構文上の区切りをスペース1文字にする。 |
| 回帰 | タグの順序を変えても検証に成功し、`@return 1` と `@exit 1` の併存を受理する。 |
| 回帰 | 混在した区切りと整形済みの区切りを同じコメント内容として解析し、本文と説明文の内部の空白を保持する。 |
| 検出範囲 | インデントされたブロックとネストした関数宣言を受理し、通常コメントで分断されたブロックや、対応する関数がないブロックを検出する。 |
| 検出範囲 | コマンド末尾、ヒアドキュメント内、引用文字列内の `##` を対象外とし、ドキュメントのない関数を受理する。 |
| 入力 | BOM や不正な UTF-8 を拒否し、LF・CRLF の混在と最終改行なしを受理する。 |
| 入力指定 | ファイルと標準入力を指定順に処理し、入力の省略、`-` の重複、ディレクトリ指定を拒否する。 |
| 整形 | 各行の改行形式と最終改行の有無を保持し、全入力の検証に成功するまで出力・上書きを開始しない。 |
| 終了コード | `fmt -d` の差分ありで `1`、差分なしで `0`、`fmt -w -` や検証違反などのエラーで `2` を返す。 |

診断と生成出力など、要確認事項に関するテストの期待値は、仕様の決定後に定義します。
