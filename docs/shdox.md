# shdox 仕様

shdox はシェルスクリプトと関数のドキュメントコメントを検証・整形し、ドキュメントを生成する CLI です。

## ドキュメントコメント

シェルの構文上コメントに当たり、行頭またはスペース・タブによるインデントの直後から `##` で始まる独立した行は、すべてドキュメントコメントの候補です。
コマンド末尾のコメントや、ヒアドキュメント・引用文字列内のコメント風文字列は対象外です。
連続する候補行を1つのブロックとします。
名前付きの関数宣言に行単位で隣接するブロックは、その関数のドキュメントです。
ファイル先頭からシバン、独立したコメント行、空行のみが連続する範囲をファイル冒頭とします。
ファイル冒頭にあるブロックのうち、関数のドキュメントに当たらないものはファイル自体のドキュメントです。
ファイル用のブロックが通常コメントや空行で分断されて複数ある場合、またはファイル冒頭以外に関数宣言と隣接しないブロックがある場合は配置エラーです。
ファイル用と関数用のブロックには、同じ構文とタグの検証規則を適用します。
`### 見出し` のように本文の区切りを欠く候補行は構文エラーです。
条件分岐内や別の関数内にある宣言にも同じ規則を適用します。
ドキュメントのない関数も許容します。
ドキュメントを付けられるのは名前付きの関数宣言です。
Zsh の匿名関数や Bats の `@test` にドキュメントを付けると配置エラーになります。
先頭のコメント空行を読み飛ばした後、次のコメント空行までの本文が必須の概要です。
概要の前にタグが現れたり、本文がないままブロックが終わったりした場合は仕様違反です。
詳細説明とタグはそれぞれ省略でき、詳細説明を書く場合は概要の後、タグの前に置きます。
概要と詳細説明の間、および詳細説明の段落間には、コメント空行を1行以上置きます。
ブロックの先頭と末尾には任意の数のコメント空行を置けます。
最初のタグの前とタグ同士の間には、任意の数のコメント空行を置けます。

```sh
#!/bin/bash
## ファイルを検証するスクリプト。

## ファイルを検証する。
##
## ファイルの存在を確認する。
## 存在しない場合はシェルを終了する。
##
## 空ファイルは検証失敗として扱う。
##
## @param $1 ファイルパス
## @return 0 検証成功
## @return 1 空ファイル
## @exit 2 ファイルが存在しない
validate_file() {
    [[ -f "$1" ]] || exit 2
    [[ -s "$1" ]] || return 1
    return 0
}
```

### 行の解析

1. 行末の水平空白を解析時に除去します。
2. `##` だけの行をコメント空行として扱います。
3. 本文のある行では、`##` の直後に水平空白が1文字以上必要です。
4. `##` 直後の水平空白をすべて読み飛ばし、最初の文字が `@` ならタグ行、それ以外なら本文行として扱います。
5. タグ行では、タグ名と後続フィールドの間、および引数と説明文の間にある連続した水平空白を区切りとして読み取ります。

水平空白は ASCII スペースと水平タブで、同じ区切り内に混在できます。
本文とタグの説明文は必須の非空文字列で、改行を含めることはできません。
本文と説明文の内部の空白は自由に記述できます。
未定義のタグ名は検証エラーです。

### EBNF

この文法は行末の水平空白を除去した後の行に適用します。

```ebnf
document    = { blank }, summary, [ gap, description ], [ { blank }, tags ],
              { blank };
summary     = paragraph;
description = paragraph, { gap, paragraph };
paragraph   = text-line, { text-line };
tags        = tag-line, { { blank }, tag-line };

gap         = blank, { blank };
blank       = "##", newline;
text-line   = "##", separator, text, newline;
tag-line    = "##", separator, tag, newline;

tag         = "@param", separator, position, separator, tag-text
            | "@return", separator, status, separator, tag-text
            | "@exit", separator, status, separator, tag-text
            | ( "@stdin" | "@stdout" | "@stderr" | "@sideeffect" ),
              separator, tag-text;

position    = "$", nonzero, { digit };
status      = "0" | nonzero, { digit };
separator   = hspace, { hspace };
hspace      = ? ASCII スペースまたは水平タブ ?;
nonzero     = "1" | "2" | "3" | "4" | "5" | "6" | "7" | "8" | "9";
digit       = "0" | nonzero;
text        = ? 水平空白と @ 以外の文字で始まる非空の行内文字列 ?;
tag-text    = ? 水平空白以外の文字で始まる非空の行内文字列 ?;
newline     = ? 行の終端 ?;
```

### タグの意味と検証規則

| タグ | 意味 | 出現回数 |
| --- | --- | --- |
| `@param <position> <description>` | 位置引数の説明 | 0回以上 |
| `@return <status> <description>` | 関数から戻る際の終了ステータスの説明 | 0回以上 |
| `@exit <status> <description>` | シェルを終了する際の終了ステータスの説明 | 0回以上 |
| `@stdin <description>` | 標準入力の説明 | 0～1回 |
| `@stdout <description>` | 標準出力の説明 | 0～1回 |
| `@stderr <description>` | 標準エラー出力の説明 | 0～1回 |
| `@sideeffect <description>` | 副作用の説明 | 0回以上 |

位置引数は `$1` 以上の正整数で、先頭にゼロを付けることはできません。
終了ステータスは0～255の整数で、`0` 以外の表記では先頭にゼロを付けることはできません。
同一ブロック内では、同じ位置引数の `@param`、同じステータスの `@return`、同じステータスの `@exit` をそれぞれ重複して記述できません。
`@return 1` と `@exit 1` のように、種類の異なるタグで同じステータスを使うことはできます。
タグの並び順は任意です。

## CLI

### 共通の入力

各コマンドは1つ以上のファイル引数を受け取り、指定順に処理します。
`-` は標準入力を表し、ファイル引数と併用できますが、指定できるのは1回だけです。
入力引数の省略はコマンドラインの構文エラーで、ディレクトリの指定は入力エラーです。
入力は BOM なしの UTF-8 とし、BOM 付きの入力や不正な UTF-8 は入力エラーです。
LF と CRLF を行の区切りとして扱い、同一ファイル内での混在と最終改行の省略を許容します。

| コマンド | 動作 |
| --- | --- |
| `shdox check [--lang LANG] FILE...` | コメントの字句、構造、配置、値域を検証する。 |
| `shdox fmt [--lang LANG] [-d \| -w] FILE...` | コメントの構文上の区切りを ASCII スペース1文字に統一する。 |
| `shdox generate [--lang LANG] FILE...` | コメントからドキュメントを生成する。 |

`check` と `generate` の入力では、構文上の区切りに ASCII スペースと水平タブを混在させることができます。
検証範囲は字句と構造までとし、関数本体の制御フローとタグ記述の整合性は検証対象外です。

### シェル方言

各入力には次の優先順で方言を適用します。

1. `--lang LANG` または `--lang=LANG` で指定した方言を、ファイルと標準入力のすべてに適用します。
2. 先頭行のシバンから方言が分かる場合は、その方言を使います。
3. ファイルの拡張子が `.bash`・`.mksh`・`.bats`・`.zsh` の場合は、対応する方言を使います。
4. 判定できなければ Bash を使います。

`--lang` の許容値は `bash`・`posix`・`mksh`・`bats`・`zsh` です。
値の欠落と未定義の値はコマンドラインの構文エラーです。
シバンは `/bin/` または `/usr/bin/` の直接指定と `env` 経由の指定を認識し、`sh` と `dash` は POSIX sh として扱います。
標準入力の自動判定にはシバンを使い、`.sh` は拡張子による判定の対象外です。
Zsh の構文解析は実験的です。

### 整形の出力

| オプション | 動作 |
| --- | --- |
| なし | 整形済みのソースを入力順に標準出力へ書き、入力間に区切り文字を追加しない。 |
| `-d` | 整形前後に差分がある入力について、前後3行の文脈を含む unified diff を入力順に標準出力へ書く。 |
| `-w` | 変更のあるファイルを指定順に整形結果で上書きする。 |

`-d` のヘッダーは `--- <入力名>` と `+++ <入力名>` とし、標準入力の入力名は `-` とします。
`-d` と `-w` の併用、および `-w` での `-` の指定はコマンドラインの構文エラーです。
すべての入力の読み取りと検証が成功してから、出力または上書きを始めます。
上書きに失敗した場合は、その時点で停止し、先に上書きしたファイルへの変更は残します。

### 整形の規則と保証

管理対象のコメント行末にある水平空白を除去します。
コメント空行は、元のインデントに続く `##` に統一します。
ブロックの先頭と末尾のコメント空行はすべて削除します。
セクション間と段落間の連続するコメント空行は、先頭行のインデントと改行形式を保持して1行にまとめます。
タグを「生成の出力」の表と同じ順序で並べ、`@param`・`@return`・`@exit` は同種内で数値の昇順に並べます。
それ以外の同種タグは記述順を保持します。
最初のタグの前にはコメント空行を厳密に1行置きます。
空行がない場合は、最初のタグ行のインデントと直前の本文行の改行形式を使ってコメント空行を挿入します。
既存のタグ行にタグを並べ直し、タグ間のコメント空行はすべて削除します。

| 性質 | 保証 |
| --- | --- |
| 冪等性 | 整形済みのソースを再度整形すると、バイト単位で同じ結果になる。 |
| 決定性 | 同じ入力を整形すると、実行ごとに同じ結果になる。 |
| 局所性 | 変更は管理対象のコメント行に限り、インデント、本文と説明文の内部の空白、残る各行の改行形式、最終改行の有無を保持する。 |
| 構造保存 | 整形結果を再解析すると、対応する関数、概要、詳細の段落、各タグの種類・引数・値・説明文が整形前と一致する。 |

### 生成の出力

すべての入力の読み取りと検証が成功してから、1つの Markdown 文書を標準出力に書きます。
入力の指定順に、ファイル自体または関数にドキュメントがある入力だけを出力します。
各入力は、引数で指定したパスをインラインコードにしたレベル1見出しで始めます。
標準入力の見出しには `-` を使います。
ファイルの概要は入力見出しの直下に置き、詳細説明とタグはレベル2見出しの下に置きます。
ドキュメント付きの関数がある場合は、`## Functions` の下に宣言順で関数を並べます。
各関数の概要は関数名をインラインコードにしたレベル3見出しの直下に置き、詳細説明とタグはレベル4見出しの下に置きます。
Zsh の複数名の関数宣言は、宣言内の名前の順に、各名前について同じドキュメントを出力します。
概要の改行と詳細説明の段落構造を保持します。
詳細説明がある場合は `Description` 見出しを出力します。
タグは次の表の順序で、種別ごとに見出しを付けて出力します。

| タグ | 見出し | 項目の形式 |
| --- | --- | --- |
| `@param` | `Param` | `- `、位置引数のインラインコード、`: `、説明文 |
| `@stdin` | `Stdin` | 説明文 |
| `@stdout` | `Stdout` | 説明文 |
| `@stderr` | `Stderr` | 説明文 |
| `@return` | `Return` | `- `、終了ステータスのインラインコード、`: `、説明文 |
| `@exit` | `Exit` | `- `、終了ステータスのインラインコード、`: `、説明文 |
| `@sideeffect` | `Side Effect` | `- `、説明文 |

該当タグがないセクションは省略します。
同種のタグ内では、`@param`・`@return`・`@exit` を数値の昇順に並べ、それ以外は記述順を保持します。
見出しと本文の間、および各セクション間には空行を1行入れます。
概要、詳細、タグの説明文は Markdown としてそのまま出力します。
どの入力にもファイルや関数のドキュメントがなければ、標準出力に何も書かず、終了コード `0` を返します。
同名の関数が複数ある場合は、ドキュメント付きの宣言ごとに、同じ名前の見出しを出力します。
生成する Markdown の改行には LF を使用します。
空でない文書の末尾には LF を1文字置きます。

```markdown
# `script.sh`

ファイルを検証するスクリプト。

## Functions

### `validate_file`

ファイルを検証する。

#### Description

ファイルの存在を確認する。
存在しない場合はシェルを終了する。

空ファイルは検証失敗として扱う。

#### Param

- `$1`: ファイルパス

#### Return

- `0`: 検証成功
- `1`: 空ファイル

#### Exit

- `2`: ファイルが存在しない
```

### 診断

すべてのコマンドは診断を標準エラー出力に書きます。
位置が分かる診断は `ファイル名:行:列: メッセージ` とし、行と列は1始まりで、列はバイト単位とします。
ファイルに関する位置情報のない診断は `ファイル名: メッセージ` とし、標準入力のファイル名は `-` とします。
コマンドラインの構文エラーは `shdox: メッセージ` として報告し、入力を読む前に終了します。
入力の読み取りや検証に失敗した場合も残りの入力を検査し、診断を入力順・行順・列順に報告します。
シェルの構文解析に失敗した場合は、パーサーの診断を報告して次の入力に進みます。
`fmt` と `generate` は、入力の読み取りや検証に失敗した場合、標準出力への出力やファイルの上書きを始めません。

### 終了コード

| 終了コード | 条件 |
| --- | --- |
| `0` | 処理に成功し、`fmt -d` の場合は差分がない。 |
| `1` | `check` でドキュメントコメントの構文・配置・タグの仕様違反を検出したか、`fmt -d` の処理に成功し、差分がある。 |
| `2` | コマンドラインの構文エラー、シェルの構文エラー、不正な UTF-8、BOM、I/O エラーなどが発生したか、`fmt`・`generate` でドキュメントコメントの仕様違反を検出した。 |

検査結果が複数ある場合は、終了コード `2` が `1` に優先します。

## 実装要件

Go で実装し、シェルの構文解析には `mvdan.cc/sh/v3/syntax` を使用します。
Go と `mvdan.cc/sh/v3` のバージョンは実装開始時に `go.mod` で固定します。
対応する構文は、採用したパーサーの各方言モードに従います。
決定した方言と `KeepComments(true)` を指定して解析し、名前を持つ `*syntax.FuncDecl` を文書化の対象とします。
コメントと関数のソース位置を照合して、独立したコメント行、ブロックの連続性、関数宣言との隣接を判定します。
